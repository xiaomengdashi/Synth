## 审阅与修复

独立只读审阅提出三项 Important，无 Critical、Minor 或放弃判断的项目；三项均补充先失败后通过的回归测试后修复：

1. 引用校验按 Markdown 节点识别，排除波浪线代码块、缩进代码及链接中的数字，保留正文的合法引用。
2. 承接式问题继承原主题与此前引用，连续多次追问仍可保持上下文；明确的新主题优先。
3. 在同会话互斥范围内重新检查请求标识，等待配置期间完成的同请求会重放已有结果。

另外修复首次提问时详情读取覆盖乐观问题的竞态、答案成功后列表刷新失败不应抹去答案、失败问题的侧栏标题刷新，以及 Markdown 中 C++ 模板参数被二次 HTML 解析抹去的问题。正文索引版本已递增，现有内容在下一次提问时自动重建。

## 实施取舍与影响

- 在当前目录建立功能分支，复用现有可运行环境；代价是当前检出分支已变为 `codex/knowledge-qa`，尚未合并或推送。
- 索引维护放在独立的 `knowledge_index.py`，正文提取与数据库生命周期分离；代价是多一个内部服务模块。
- 存储注册、唯一约束和中断恢复使用一项真实临时库集成测试共同覆盖，另测 FTS 缺失；代价是同一测试中的失败需要通过 traceback 区分场景。
- Vite 支持 `SYNTHAI_BACKEND_URL`，便于隔离测试；默认仍连本地 8000，使用自定义后端时需设置该变量。
- 状态查询以 HTTP 200 返回配置和索引可用标志，生成接口遇到缺配置则返回 503；调用状态接口的客户端需要检查字段。
- 引入并声明 `markdown-it-py[linkify]==4.0.0`，以 Markdown 语法树校验引用；服务器部署需随 requirements 安装此依赖，本地虚拟环境已安装。

## 使用边界

首版为词面检索，同义表述的召回存在局限，可使用具体关键词。引用编号有效不能自动证明每项结论都被资料支持，需结合可查看的原文核对。会话互斥按当前单工作进程部署实现，多工作进程需数据库租约。

部署脚本当前反向代理读取/发送超时为 300 秒；如提高后台模型超时，应同步调整代理。此次验证覆盖本地实际链路，未发布到远端服务。
