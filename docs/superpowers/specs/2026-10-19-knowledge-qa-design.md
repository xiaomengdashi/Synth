# SynthAI 全库 AI 问答设计

日期：2026-10-19
状态：2026-10-19 已实现并通过回归、浏览器及真实模型验证

## 1. 已确认的目标

用户选择实现「全库 AI 问答」，并确认以下首版范围：

- 增加知识库问答页面，支持连续追问。
- 检索已入库文章正文，以相关段落作为模型回答依据。
- 回答带编号引用，展示文章标题、来源和正文片段，可打开原文章。
- 资料不足时明确说明，不把模型常识伪装为库内结论。
- SQLite 保存会话，支持新建、切换和删除。
- 仅管理员使用，沿用现有后台访问令牌和模型服务配置。
- 首版使用本地文本检索，不要求另外配置 Embedding 模型或搜索服务。

成功标准：用户可以询问库内技术内容、结合上轮问题追问、检查答案引用并回到文章阅读；刷新后仍能看到会话。

## 2. 当前代码依据

- `backend/app/models/article.py`：正文在 `content_md`，同时保存标题、摘要、来源、分类、更新时间。
- `backend/app/services/note_export.py`：`extract_note_body` 已覆盖 HTML 文章、X 长文 JSON、X 推文 JSON 和普通 Markdown。检索复用此提取入口，再清除脚本、样式和非正文标记；不直接把整个富内容 JSON 或 HTML 标记作为资料。
- `backend/app/services/llm_client.py`：现有 OpenAI 兼容客户端读取服务端 Base URL、API Key 和模型名，以流式方式请求上游并返回完整字符串。
- `backend/app/routers/config.py`、`services/settings_store.py`：现有服务端模型配置读取入口。
- `backend/app/routers/admin_auth.py`：现有 `require_admin` 在首次未设置令牌时放行；问答属于可触发模型计费的功能，需要在新路由内额外要求令牌已初始化，再复用令牌校验。不调整其他接口的首次部署行为。
- `frontend/src/components/AdminLayout.tsx`：后台已有令牌入口、侧栏和独立主题。
- `frontend/src/utils/adminAuth.ts`：`adminFetch` 自动携带 `X-Admin-Token`。
- 当前本机 Python 的 SQLite 3.54.0 已确认支持 FTS5；部署启动时也要检测，缺失时只将问答功能标记为不可用，保留文章阅读与导入功能。

## 3. 方案选择

推荐采用 SQLite FTS5 段落检索，再由当前配置的聊天模型组织答案。

| 方案 | 优点 | 代价与边界 |
| --- | --- | --- |
| 本地段落检索 + 当前聊天模型 | 沿用 SQLite 和现有模型配置，检索结果可解释，通常每轮只需一次回答生成 | 同义改写的召回弱于语义向量检索 |
| 向量检索 | 对不同措辞表达的同一概念召回更好 | 需要 Embedding 配置、索引重建与维度版本管理 |
| 整库直接发送给模型 | 小样本实现简单 | 内容量增长后上下文和费用不可控，无法稳定覆盖整库 |

首版明确展示「根据已保存文章回答」。未召回资料只说明当前检索未找到足够依据，不宣称整库绝对不存在该信息。

## 4. 页面与用户流程

页面路由为 `/admin/ask`，后台侧栏增加「知识库问答」，沿用后台主题与移动端导航。前台导航仅在管理员身份验证通过后显示该入口，目标同为 `/admin/ask`。

桌面为会话列表与对话区；手机上会话列表可收起。页面包含：

- 新建会话、历史会话标题、最近更新时间和删除动作。
- 问题输入区，发送按钮，Enter 发送、Shift+Enter 换行。
- 用户问题、Markdown 答案、编号引用和资料卡片。
- 引用卡片由服务器返回的标题和原文片段组成；点击文章标题打开 `/article/:id`，在新标签页阅读，保留当前问答。
- 发送后显示「正在查找资料并生成回答」并禁止同会话重复提交。
- 每条失败问题提供显式重试入口，重试使用新请求标识，不自动重复调用模型。
- 尚无文章、未配置模型、模型调用失败、权限失效和索引不可用均显示对应状态及必要的配置入口。

首版前端在一次请求完成后展示完整回答；上游仍复用现有流式客户端。页面不虚构逐字输出进度。用户切换会话时保留正在进行的请求和完成后的结果，避免结果写入当前显示的另一会话。

## 5. 正文索引与检索

### 5.1 正文标准化与分段

新增 `services/knowledge_retrieval.py`，集中处理正文提取、分段、分词和检索。

- 以 `extract_note_body(content_md)` 为入口，保留标题与段落文字，移除 HTML 的 script/style、富内容 marker、媒体 URL 噪声和不可见字符。
- 以段落边界切分，目标每段 900 字符，硬上限 1,200 字符；超长段按句子再按字符切分，相邻段最多重叠 120 字符。
- 每个片段保存文章 ID、顺序、正文和版本，不能只索引正文前若干字符；超长文章以更多片段覆盖全文。
- 空正文、损坏的富内容块不拿标题或摘要冒充正文；作为不可检索文章计数返回。
- FTS 的标题列和正文列分别索引。英文单词小写化；连续中文生成相邻双字词，并保留单字查询的独立词元。提问和文档使用相同规则。
- 问题过滤固定问句停用词，查询词上限 48 个。所有 FTS 查询均由已转义的词元构造，用户文本不直接拼接 MATCH 表达式或 SQL。

### 5.2 索引同步

增加索引元数据表和片段表，FTS5 表独立管理。

每轮生成前进行增量同步，流程为：

1. 扫描全部文章的 ID、`updated_at`，与索引版本记录比较，不限制为最新 N 篇。
2. 仅批量读取新增、更新文章的标题和正文，计算内容摘要并更新其片段；内容未变时更新版本记录即可。
3. 删除原文章已不存在的索引和 FTS 行。
4. 在受锁保护的短事务中分批提交；完成检索后结束数据库事务，再请求模型，避免长时间持有 SQLite 写锁。每批先在事务外完成正文提取，再提交该批索引；任一批失败则本次提问报错，下轮同步继续补齐。

文章新增、重新获取、HTML 导入、邮件导入和删除都由这条统一同步路径覆盖，不依赖每个导入入口各自触发索引。

索引记录保存提取算法版本。算法升级时通过版本差异重建；索引可从文章表完整恢复，不修改原文章。首轮构建使用有界批次并将 CPU 密集提取放到工作线程，避免阻塞异步事件循环。

文章在本轮检索后被更新或删除时，本轮保存的资料是检索当时的正文快照；下轮提问使用新版本。

### 5.3 检索与上下文预算

- 以 FTS5 BM25 排序，标题命中加权。
- 当前问题作为主要查询，最近两条用户问题与上一轮引用文章作为补充，支持「再展开讲讲」等追问。
- 先检索最多 60 个候选片段，去掉重叠内容，优先保留多篇文章，最多使用 12 个片段、每篇最多 3 个。
- 正文上下文总上限 14,400 字符，历史对话最多最近 6 轮且总上限 8,000 字符，当前问题上限 2,000 字符。
- 这些是发送给模型的预算，不限制索引覆盖范围。
- 没有有效查询词或相关片段时，直接保存明确的资料不足结果，不调用回答模型。

本地文本匹配存在同义词和概括问题召回不足的边界。首版不另外隐式调用模型改写搜索词，也不引入额外模型配置。

## 6. 回答与引用

新增 `services/knowledge_qa.py`，负责构造上下文、模型调用和结果验证。

- 按本轮检索结果分配 `[1]`、`[2]` 等引用编号，每个编号对应一个确定片段。
- 给模型提供编号、文章标题和正文；资料以结构化数据和明确边界包裹，提示资料中的指令是内容而非系统要求。
- 系统要求只依据资料回答、按用户语言组织内容、关键结论附编号，无法支持的部分说明依据不足。
- 模型返回 JSON：`answer` 为带编号的 Markdown，`insufficient_evidence` 为布尔值。只剥离可选代码围栏后解析，不把错误 JSON 直接当成成功答案。
- 服务端校验所有引用编号都属于本轮片段；非「依据不足」的回答必须至少包含一条有效引用。引用损坏或输出结构错误时返回明确失败，不自动用无引用回答代替。
- 返回和保存的引用内容均由服务器从命中片段产生，模型不能自行填写标题、正文摘录、文章 ID 或链接。
- 仅返回实际引用的资料卡片。Markdown 中的引用编号由前端渲染为本轮资料的定位按钮，资料卡片提供服务器构造的文章链接。
- 引用编号验证只保证来源存在，不能自动证明每句话都被资料支持；用户可查看保存的原文片段核对。

复用 `chat_completion`，显式设置回答输出上限为 `min(4096, 后台 llmMaxTokens)`，温度 0.2，超时沿用后台配置。问答路由从服务端读取配置，不接收客户端指定的 Base URL、API Key 或模型覆盖。

当前客户端会对部分网络失败重试，可能发生重复计费；页面不再增加自动重试。无效引用或格式错误不触发额外模型调用。

## 7. 会话与数据模型

新增 `backend/app/models/knowledge.py`，由现有 `Base.metadata.create_all` 建表。

### KnowledgeConversation

- `id`：UUID 主键。
- `title`：首个问题截取最多 40 字符，不额外请求模型生成标题。
- `created_at`、`updated_at`：UTC 时间，接口沿用项目时区编码。

### KnowledgeTurn

- `id`、`conversation_id`、`request_id`：`conversation_id + request_id` 唯一，防客户端重复发送造成重复生成。
- `question`、`answer`、`status`（pending/completed/failed/interrupted）。
- `insufficient_evidence`、`sources_json`（编号、文章 ID、标题、来源类型、正文片段、文章版本）。
- `error_message`：受控中文错误，不保存上游响应、API Key 或完整配置。
- `created_at`、`completed_at`。

### KnowledgeIndexedArticle 与 KnowledgeChunk

- IndexedArticle 保存文章 ID、文章更新时间、内容摘要、索引版本和可检索状态。
- Chunk 保存整数行 ID、文章 ID、片段序号、正文。
- `knowledge_chunks_fts` 保存相同整数行 ID 下的已分词标题和正文，由索引服务显式同步。
- 片段按文章 ID 和顺序建索引；会话轮次按会话 ID 和创建时间建索引。

删除会话显式删除其轮次，适配当前 SQLite 未统一启用外键级联的状态。历史引用保存快照；原文章被删后，历史正文片段仍可读，文章链接标记「原文章已删除」。

同一会话只允许一个进行中的请求，返回 409 提示稍后重试；不同会话允许独立提问。新路由采用进程内锁，符合当前单进程部署；部署多个工作进程前需将生成互斥迁移为数据库租约。

进程启动时将遗留 pending 轮次标记 interrupted，提示重新提问。生成前先保存问题，完成时再保存答案；异常或取消时落对应失败状态并释放锁。

## 8. API

统一前缀 `/api/v1/knowledge`，所有接口要求初始化后的有效管理员令牌。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/status` | 返回模型是否配置、索引是否可用、文章数与已索引数；不返回模型密钥 |
| GET `/conversations?limit=30&offset=0` | 最近更新排序的会话列表及总数 |
| POST `/conversations` | 新建空会话 |
| GET `/conversations/{id}` | 获取会话及已保存轮次、引用快照、文章是否仍存在 |
| DELETE `/conversations/{id}` | 删除空闲会话及轮次；生成中返回 409 |
| POST `/conversations/{id}/messages` | 接受 `{question, request_id}`，生成并返回完整轮次 |

问题做 trim 后长度校验。未知会话返回 404；权限失败 401；令牌未初始化、模型未配置、FTS5 不可用返回 503 并附受控中文说明；同会话忙返回 409；上游失败返回 502；超时返回 504。未找到资料属于成功的 completed 轮次，`insufficient_evidence=true`。

重复 request_id：已完成时返回现有结果；pending 时返回 409；已失败时返回已有失败状态，不自行再次调用模型。用户显式重试生成新的 request_id。

## 9. 代码边界

- `models/knowledge.py`：会话、轮次、索引记录、片段的 ORM 模型。
- `services/knowledge_retrieval.py`：正文处理、FTS 初始化、增量同步、检索。
- `services/knowledge_qa.py`：引用、提示词、答案验证和模型调用。
- `routers/knowledge.py`：鉴权、输入校验、会话生命周期与响应。
- `database.py`、`models/__init__.py`、`main.py`：模型注册、幂等初始化、路由注册。
- `frontend/src/features/knowledge/`：类型、API 客户端、引用处理、问答页面和样式。
- `App.tsx`、`AdminLayout.tsx`、`Layout.tsx`：路由与入口。
- README：补充入口、现有模型配置要求、本地检索边界和首次索引说明。

## 10. 验证标准

实现时使用临时数据库和模型响应替身验证核心行为，不向真实模型发送测试文章。

1. 标题和摘要没有关键词、只有正文含关键词的文章可以被召回；中文和英文均覆盖。
2. 很早导入的文章、超长文章尾部段落、不同平台正文均进入索引。
3. 新增文章、重新获取、修改标题、删除文章后，下轮检索反映变化；旧会话引用快照仍保留。
4. 连续追问可以沿用上一轮主题；整库无匹配、空库时不调用模型。
5. 无权限和未初始化令牌无法触发问答、读取或删除会话。
6. 引用不存在、回答缺引用、JSON 损坏与空模型输出均不作为正常有据答案保存。
7. 同请求幂等、同会话互斥、生成失败与进程中断状态恢复可重复验证。
8. 会话新建、列表、切换、刷新恢复和删除正常，切换时不会串写回答。
9. 前端类型检查和生产构建通过；真实浏览器检查桌面与手机宽度下的入口、输入、引用跳转、加载和错误状态。
10. 真实模型连通检查仅在已有可用配置、且能使用已入库资料时进行；若缺配置，明确报告未验证真实生成。

## 11. 设计自查

- 已明确数据来源、平台正文格式、索引更新入口与全库覆盖边界。
- 已明确权限和模型配置来源，匿名访问不会产生问答模型调用。
- 已明确引用是服务端正文快照，编号验证不等于事实正确性证明。
- 已明确会话保存、重复请求、并发、失败和中断处理。
- 已明确首版检索方式、资源预算和部署依赖，不依赖未配置的 Embedding 模型。
- 代码实施前需用户审阅本文，再编写实施计划并确定执行方式。
