## 总体判断

现有方向值得保留：前台围绕阅读与收藏，后台围绕内容和配置；已有主题变量、列表/卡片视图、阅读进度、目录、笔记、危险操作确认，以及部分移动端卡片布局。应先修复列表完整性、状态反馈和表单保存行为，再统一视觉细节。

P1 表示会影响核心操作或展示正确性，P2 表示明显体验摩擦，P3 表示可在之后完善的能力。

## 优先修复的确定问题

### 1. P1：后台文章列表只能看到前 50 篇

- `AdminArticles` 调用 `fetchArticles({ reset: true, all: true })`。
- Store 中 `all` 只把单页大小设为 50，并没有遍历全部分页；文章管理页也没有加载更多或翻页控件。
- 当匹配结果超过 50 篇时，用户无法沿列表访问后续文章。“库内共”还直接使用筛选请求的 `total`，实际是当前筛选总数。
- 建议：使用明确分页，显示“匹配 N 篇，当前第 X–Y 篇”；全库总数单独获取；批量全选明确限定为当前页。
- 证据：[后台文章列表](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminArticles.tsx:104)、[分页实现](/Users/kolane/SynthAI/frontend/src/features/app/store/useAppStore.ts:169)。

### 2. P1：后台手机端搜索被隐藏

- 文章管理组件专门给手机搜索设置了 100% 宽度，但 `max-width: 700px` 的 CSS 对 `.ac-search` 设置 `display: none`。
- 建议：保留全宽搜索栏，来源和分类放在下一行；筛选后提供“清空筛选”。
- 证据：[搜索入口](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminArticles.tsx:171)、[隐藏规则](/Users/kolane/SynthAI/frontend/src/index.css:1034)。

### 3. P1：前台“最早”不是全库最早

- 后端固定按创建时间倒序分页，前台仅对已加载数组做升序排序。
- 例如库存 100 篇、已加载最新 20 篇时，“最早”会显示这 20 篇中最早的一篇；继续加载会在列表前方插入更早的数据。
- 建议：排序参数传到后端，切换排序时重置分页；排序条件纳入请求状态标识。
- 证据：[前台排序](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Articles.tsx:74)、[后端排序](/Users/kolane/SynthAI/backend/app/routers/articles.py:71)。

### 4. P1：后台“网页链接”来源筛选契约不一致

- 前端发送 `source=__other`，后端直接执行 `Article.source_type == source`，没有把 `__other` 解释为其他来源集合。
- 建议：前后端共享来源枚举；如果“网页链接”代表所有其他类型，就在后端明确实现集合筛选，并统一前台的来源标签。
- 证据：[筛选值](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminArticles.tsx:182)、[查询条件](/Users/kolane/SynthAI/backend/app/routers/articles.py:49)。

### 5. P1：模型设置的分区保存会丢失其他分区的编辑

- 连接、转写、生成参数分别持有整个配置的本地副本，并在共享 `config` 改变时执行 `setLocalConfig(config)`。
- 修改连接字段但未保存，再修改并保存生成参数时，共享配置更新会把连接区域的未保存输入重置。
- 建议：每个分区只保存自己的字段并独立维护草稿；或整页使用统一草稿和一个保存栏。增加“未保存”标识和离开提醒。
- 证据：[设置分区](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminModelSettings.tsx:16)、[配置保存](/Users/kolane/SynthAI/frontend/src/features/app/store/useAppStore.ts:128)。

### 6. P1：总览趋势图可能漏算

- 总览也是取前 50 篇，再按天统计这批文章。近七天新增超过 50 篇时，图表不能代表完整增长趋势。
- 建议：增加按日聚合统计接口，图表展示全量统计；失败时显示不可用与重试，不使用部分数据暗示全量结果。
- 证据：[按数组计数](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/Admin.tsx:37)、[总览加载](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/Admin.tsx:171)。

## 前台体验优化

### 7. P1：导入应有可持续查看的进度与结果

- 提交前立即清空链接；提交失败后没有恢复输入。
- 首页只把按钮改为“处理中”，虽然维护了任务状态，却没有显示当前任务卡片、处理阶段或结果文章链接。
- 轮询最多约四分钟，网络异常被忽略，超时直接把本地任务记为失败；此时服务端可能仍在处理。
- 建议：输入框下显示当前任务，包含链接、状态、阶段、查看文章/查看任务入口；区分“处理失败”“状态获取失败”和“仍在后台处理”；失败保留链接，并提供用户主动重试。
- 证据：[轮询与提交](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Home.tsx:77)。

### 8. P2：统一空、加载、错误三类状态

- 后台文章列表两次判断同一个 `articles.length === 0`，所以“没有符合筛选条件的文章”分支不可达。
- 首页没有消费文章加载/失败状态；分类页也未完整区分这些状态。
- 详情页将非成功响应和网络失败统称“文章未找到，可能已被删除”。
- 建议：统一状态组件：首次空库给导入入口；无匹配给清空筛选；加载给骨架或状态提示；网络/服务错误给重试；只有 404 才提示文章不存在。
- 证据：[后台空状态](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminArticles.tsx:293)、[分类页](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Categories.tsx:101)、[详情错误](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Article.tsx:289)。

### 9. P2：命名和提示语围绕读者任务统一

- 首页“最近收藏”实际展示最近导入，而文章库“只看收藏”指星标，两个含义混用。
- 分类空状态仍引导到“系统配置 → 文章分类”，实际导航在“内容 → 文章分类”。
- “微信安全验证不会自动打开浏览器”等文案解释实现细节，却没有告诉用户失败后如何继续。
- 建议：最近导入、星标文章、分类三个概念分开；错误旁提供对应入口；平台按钮改为自动识别结果或支持范围说明，减少无必要的手动选择。
- 证据：[首页文案](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Home.tsx:267)、[分类指引](/Users/kolane/SynthAI/frontend/src/features/articles/pages/Categories.tsx:65)。

### 10. P2：窄屏阅读与信息密度需要实机验证

- 列表标题固定单行省略，手机上长中文标题识别成本较高；建议两行标题、一行摘要，并保留来源与阅读状态。
- 目录在 1279px 以下移到正文上方，最高可占 34vh；建议窄屏默认折叠目录，减少到达正文前的滚动。
- 排序、阅读工具、后台小按钮高度多为 28px；建议触屏环境增加到 40–44px 的舒适点击区。
- 次级文字多为 11–12px，建议重点操作和说明提升到 13–14px，具体留白与换行以截图验证为准。
- 证据：[列表标题](/Users/kolane/SynthAI/frontend/src/index.css:243)、[阅读工具](/Users/kolane/SynthAI/frontend/src/index.css:292)、[响应式阅读布局](/Users/kolane/SynthAI/frontend/src/index.css:513)。

## 后台与共用交互优化

### 11. P2：任务页应支持排错，而不只是展示记录

- 当前没有状态筛选、链接搜索、失败重试或错误详情操作。
- 已完成任务的主要操作包含删除文章，失败任务反而没有恢复操作。
- 刷新失败只写控制台，页面仍声称每五秒自动刷新，无法判断数据是否过时。
- 建议：提供“全部/处理中/失败/完成”筛选、上次成功刷新时间、错误摘要、配置跳转及主动重试。重试可能重新产生服务费用，应给出清楚提示且不自动触发。
- 证据：[任务页](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminTasks.tsx:40)、[任务刷新](/Users/kolane/SynthAI/frontend/src/features/app/store/useAppStore.ts:219)。

### 12. P2：补齐弹窗、提示与导航的可访问性

- 确认弹窗虽然有 dialog 语义，但没有焦点进入、焦点约束、Escape 关闭和关闭后的焦点恢复逻辑。HTML 导入弹窗同类。
- Toast 统一在 2.6 秒后消失，没有 live region；错误信息难以持续查看或由辅助技术获知。
- 后台移动侧栏关闭仅改变 transform，没有同时移出 Tab 顺序或设置 inert，存在焦点进入屏外导航的风险。
- `AdminPageHeader` 用摘要代替页面主标题，建议恢复语义化 h1，并把面包屑保持为路径信息。
- 建议：统一弹窗基础组件；成功消息短暂显示，错误保留至关闭并提供恢复操作；抽屉管理焦点与背景交互；实机测试键盘路径。
- 证据：[确认弹窗](/Users/kolane/SynthAI/frontend/src/components/ConfirmDialog.tsx:25)、[Toast](/Users/kolane/SynthAI/frontend/src/components/ToastStack.tsx:24)、[后台导航](/Users/kolane/SynthAI/frontend/src/components/AdminLayout.tsx:108)、[页面标题组件](/Users/kolane/SynthAI/frontend/src/features/tasks/components/AdminPageHeader.tsx:7)。

### 13. P2/P3：后台导航与管理效率

- 登录页在未登录时就写“令牌已在本机保存”，建议改为登录成功后的行为说明。后台没有明确退出入口，建议提供“退出并清除此设备令牌”。
- 总览可优先展示待处理、失败任务、服务是否可用以及提交链接入口，让管理者在后台完成日常工作。
- 划线笔记的引用和笔记正文使用截断单元格，长内容主要靠 title 查看；建议行展开或详情抽屉，手机用卡片。
- 分类可补重命名、每类数量、排序以及合并；删除前展示受影响文章数。
- TikHub 查询已有错误、重试、分页和计费说明，可以作为其他后台列表状态设计的参考。
- 证据：[登录页](/Users/kolane/SynthAI/frontend/src/components/AdminGate.tsx:136)、[笔记页](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminNotes.tsx:163)、[分类管理](/Users/kolane/SynthAI/frontend/src/features/tasks/pages/AdminCategories.tsx:88)。

## 推荐实施顺序与验收

1. **展示正确性**：后台分页、最早排序、来源筛选、统计口径。用超过 50 篇且跨多日的测试数据验证；搜索与筛选总数准确，最早项从第一页可见。
2. **核心流程**：手机搜索、导入任务卡、错误重试、分区草稿隔离。验证 390px 宽屏、提交失败、网络中断、同时编辑两个配置分区。
3. **一致性**：空状态、标题、按钮、Toast、弹窗、侧栏焦点。用键盘走通打开/取消/返回，确认错误可持续查看。
4. **视觉打磨**：核对 390/768/1440px 的实际截图，以及浅色、深色、长标题、长文章、空数据、大列表下的布局。保留现有前台阅读风格与后台高密度管理风格，统一品牌、间距和交互规范。
